# Interaction Ledger & Reporting Pipeline (Assignment A)

A Python + PostgreSQL pipeline that ingests lead CSV uploads and call-event JSONL files, keeps an
append-only interaction ledger, protects PII at rest, and produces five reports.
Design decisions, assumptions and limitations are in the repo-root [`SUBMISSION.md`](../SUBMISSION.md).

## Technology stack

Python 3.12, PostgreSQL 16, SQLAlchemy 2.x, psycopg 3, Alembic, Pydantic 2 (schema models),
`cryptography` (Fernet), pytest. Standard library `csv`, `json`, `datetime`, `decimal`, `hashlib`, `hmac`.
No other infrastructure.

## Prerequisites

* Python 3.12+
* PostgreSQL 16. The repo-root `docker-compose.yml` provides one:
  `docker compose up -d` (user `au`, password `au_local_only`, database `au_assignment`, port 5432).

## Installation

Run from the repository root:

```bash
python3 -m venv .venv && source .venv/bin/activate
pip install -r solution/requirements.txt
cd solution            # all commands below run from solution/
```

## Environment variables

Copy `.env.example` to `.env` (git-ignored) or export them. Nothing secret is hard-coded.

| Variable | Meaning |
|---|---|
| `DATABASE_URL` | e.g. `postgresql+psycopg://au:au_local_only@localhost:5432/au_assignment` |
| `PII_ENCRYPTION_KEY` | Fernet key(s), comma separated for rotation (first encrypts, all decrypt) |
| `PII_HMAC_KEY` | secret (>= 32 chars) for the keyed phone-lookup hash |
| `SCHEMAS_DIR` | optional; default `../assignment-a-data/schemas` |

```bash
python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"   # PII_ENCRYPTION_KEY
python -c "import secrets; print(secrets.token_urlsafe(48))"                                # PII_HMAC_KEY
```

Losing `PII_ENCRYPTION_KEY` makes stored PII unrecoverable, and changing `PII_HMAC_KEY` breaks lead/event
matching for existing data. Treat both like database credentials.

## Database setup

```bash
python -m src.main migrate        # same as: alembic upgrade head
```

## Ingest and report

```bash
python ../assignment-a-data/tools/generate_data.py --seed 42 --scale small --out data   # data/ is git-ignored
python -m src.main ingest data/drop_1
python -m src.main report --out reports/          # intermediate report
python -m src.main ingest data/drop_2
python -m src.main report --out reports/          # final report
python -m src.main ingest data/drop_1 data/drop_2  # re-ingest: changes nothing
```

`ingest` accepts several drop directories and processes them in the order given (one transaction each).
Exit codes: `0` success, `1` configuration / input error (message on stderr), `2` database error.

## Tests

```bash
export DATABASE_URL=...   # tests create and drop temporary databases on this server (needs CREATE DATABASE)
python -m pytest
```

Unit tests need no database. Integration and end-to-end tests clone a migrated template database per test.
End-to-end tests run the unmodified supplied generator for seeds 42, 7, 2026 and 12345 and compare the
pipeline with `tests/reference_model.py`, an independent single-pass implementation of the README rules.

## Project layout

```
solution/
  alembic.ini, migrations/        schema + append-only triggers (autogenerated, then reviewed and extended)
  src/
    main.py            CLI (argparse)             config.py / logging_setup.py
    database.py        engine, migrations, advisory lock
    models.py          SQLAlchemy models (table purposes documented in the module docstring)
    schemas.py         workflow schemas + disposition catalogue, loaded dynamically
    normalizers.py     pure: header / phone / date / decimal / enum rules
    timestamps.py      pure: UTC / offset / naive-IST parsing, IST helpers
    lead_parsing.py    pure: CSV reading + row validation      lead_ingestion.py   DB: create / merge leads
    event_parsing.py   pure: JSONL line parsing               event_ingestion.py  DB: dedupe, link, ledger, quarantine
    linking.py         orphan resolution (phone path + call_id path)
    ingest.py          one drop = one transaction, file hash tracking
    derived.py         pure: calls, effective disposition, buckets
    reporting.py       the five report files
    security.py        Fernet encryption + HMAC lookup hash
  tests/
```
